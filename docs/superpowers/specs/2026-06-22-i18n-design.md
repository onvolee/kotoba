# Kotoba UI i18n Design

## Context

Kotoba already has ADR 0029, which selects `react-i18next` for UI internationalization. The first supported UI languages are English and Simplified Chinese. The default follows the browser language and falls back to English when unsupported. Users can override the UI language in Settings, and that preference is stored in extension local storage.

The i18n layer only owns Kotoba UI controls and explanatory text. Source content and translation output remain user data and are not translated by the UI i18n system.

## Public Behavior

- When no UI language preference is saved, Kotoba resolves the initial UI language from the browser language.
- `en` and English regional variants resolve to English.
- `zh`, `zh-CN`, and Simplified Chinese-compatible browser language values resolve to Simplified Chinese.
- Unsupported browser languages fall back to English.
- Settings exposes three UI language choices: follow browser language, English, and Simplified Chinese.
- Choosing a language in Settings updates pending form state only.
- The UI language is applied and saved only after the user clicks `Save changes`.
- Returning to the workspace before saving keeps the previously active UI language.
- A saved preference is reused when the workspace is rendered again.

## Architecture

The i18n module is the primary seam. It hides browser language normalization, storage keys, resource bundles, fallback rules, and i18next setup behind a small interface.

Expected module responsibilities:

- initialize workspace i18n before React renders;
- resolve effective language from saved preference plus browser language;
- read and write UI language preference through extension local storage;
- expose supported language options for Settings;
- provide translation resources for the workspace and settings UI.

React pages should not read extension storage directly for language behavior. They should use `react-i18next` for text and a small language preference hook or helper for Settings state.

## Storage

The stored value represents the user's preference, not necessarily the current effective language:

- `browser`: follow browser language;
- `en`: force English;
- `zh-CN`: force Simplified Chinese.

The default preference is `browser`. Saving `browser` stores that preference so the user's explicit choice can still be represented in Settings.

## Testing

Tests should exercise behavior through the rendered `<App />` and visible UI text where practical.

TDD slices:

1. Browser language defaults to Simplified Chinese when no preference is saved.
2. Selecting Simplified Chinese without saving does not change the active workspace language.
3. Selecting Simplified Chinese and clicking `Save changes` changes the workspace UI language.
4. A saved Simplified Chinese preference is reused on the next render.

Storage is a system boundary, so tests may use a lightweight fake for extension local storage. Internal i18n helpers should not be tested through private implementation details.

## Out of Scope

- Translating source content or translation output.
- Adding more UI languages.
- Lazy-loading translation bundles.
- Changing translation direction labels beyond translating their UI language names.
